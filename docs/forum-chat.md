# Forum chat setup

Set `FORUM_TYPE_CHANNEL` in `.env` to the numeric ID of a Discord **Forum** channel:

```dotenv
FORUM_TYPE_CHANNEL=123456789012345678
OPENAI_MODEL=gpt-6-ultra
FORUM_MODELS=claude-opus-5.5
```

`FORUM_TYPE_CHANNEL` is optional. When it is absent, the bot keeps its existing command, mention, wake-name, and reply behavior. When present, the bot checks that it can access the channel and that it is a Forum channel before starting. The bot adds one tag for each endpoint that lists `OPENAI_MODEL`, and one tag for each endpoint that lists a comma-separated model ID in `FORUM_MODELS`. A tag is `provider/model`, for example `openai/gpt-4o-mini` or `backup/gpt-4o-mini`. Discord keeps the visible name to 20 characters, so a longer label drops a repeated provider word and a trailing date: `claude/claude-opus-5-5` is shown as `claude/opus-5-5`. The answer still ends with the full model id. A forum model may use `.` or `-`, and a short name selects one longer catalog id when that match is unique. The example model IDs are placeholders. List every model on an endpoint in `endpoints.json` (see `endpoints.example.json`). When that file is absent, every forum model uses `OPENAI_API_BASE_URL` and `OPENAI_API_KEY`, and the tag uses that endpoint's provider name. A reply ends with `provider/model`, showing which attempt answered. The selected tag is tried first. If that provider is not `openai` and the attempt fails, the bot continues on the endpoint named `openai` (or the first endpoint when none has that name): the same model, then that endpoint's other models, up to four attempts. `FALLBACK_MODEL` replaces those other models with one listed `provider/model` pair. It does not try the remaining providers. The first answer message also has a 🔄 reaction and a Change model button. The member who wrote the post or comment can add that reaction once to ask for another answer. The next try is the 🔄 on that new answer. Change model asks which forum model to use, then posts a new answer with that model and leaves the post's tags unchanged. `FORUM_MODELS` may be omitted for a single-model forum.

On startup, the bot deletes the forum's tags and registers the model tags from the environment, in that order. When those names are already the only tags and they are in the same order, the existing tag ids stay. Discord allows at most 20 forum tags, with names of at most 20 characters. Give the bot **View Channel**, **Read Message History**, **Send Messages in Threads**, **Manage Threads**, **Manage Channels**, and **Add Reactions** permissions for the forum. Enable the **Message Content** privileged intent in the Discord developer portal; the bot already requests this gateway intent.

Members start a chat by making a new forum post with any title. The opening message can be text, images, files, or a mix of those. They can select model tags to choose the model for that post. If several model tags are selected, the bot uses the earliest tag in `FORUM_MODELS` order, and within one model the endpoint order from the config, regardless of the tags' order in Discord. `OPENAI_MODEL` has the lowest priority unless it is also listed in `FORUM_MODELS`. If no model tag is selected, the bot adds the default `provider/model` tag and uses that pair. The bot comments with an answer and then replaces the post title with a short summary. Any member can continue by sending a comment in that post. A comment can include text, images, and files. Changing the model tags changes the model for subsequent answers. Existing posts in the forum are not enrolled; the bot records the first activation time in `.knownsphere_forum_state.json`, so eligible posts continue working after restarts. Changing `FORUM_TYPE_CHANNEL` starts a new activation time for the newly configured forum.

The bot reads recent visible messages from each post for context, including attachments on those messages. Images (PNG, JPEG, GIF, and WebP) and PDFs are sent to the selected model. Text files are inlined into the transcript. Other file types are named only, so the model knows they were attached but does not receive their bytes. One request includes at most 4 images, 2 PDFs, and 4 text files, at most 12 MB of attachment bytes in total, preferring the newest. An image over 5 MB, a PDF over 8 MB, or a text file over 256 KB is left unread, and text that is included is clipped to 8000 characters. Attachment text is untrusted data. A memory request still has to be in the member's own typed text; file contents are not sent to the memory router. Edits and deletions in Discord affect later answers. Existing chat behavior outside eligible forum posts continues as before. To start a fresh forum conversation, create another post.
